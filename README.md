### 1.2. Статистична однорідність вибірок

| Параметр | Значення |
| --- | --- |
| Спосіб організації | суцільна (серійна) вибірка: перший неперервний фрагмент тексту від початку твору. Розбиття на підвибірки механічне: послідовно по 1000 слововживань |
| Обсяг вибірки | **20 000 слововживань** на кожен текст (N) |
| Кількість підвибірок | **20** по 1000 слововживань |
| Обсяг повного тексту | ~31,9 тис. слів (Хвильовий), ~30,0 тис. слів (Коцюбинський) |

Обсяг вибірки обрано 20 000, як рекомендовано в методичці. Він становить близько 2/3 усього тексту повісті, тому вибірка дуже повно відображає лексику твору. Після токенізації таблиця `words` містить рівно 20 000 слововживань для обох текстів, тобто збільшувати обсяг не довелося (усі 20 підвибірок мають по 1000).

**Достатність обсягу (відносна похибка).** Для частоти слова з імовірністю p відносна похибка оцінки при довірчій імовірності 95 % обчислюється як

δ = 1,96 · √((1 − p) / (N · p)),  де p = f / N.

Для N = 20 000:

| Абсолютна частота f | 10 | 20 | 50 | 100 | 200 | 500 | 1000 | 5000 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| Відносна похибка δ, % | 62,0 | 43,8 | 27,7 | 19,6 | 13,8 | 8,7 | 6,0 | 2,4 |

Висновок: обсяг достатній для надійного статистичного аналізу частин мови (частоти від ~1000 до ~7000, похибка < 6 %) та найчастотніших лем (f ≥ 200, похибка ≲ 14 %). Для рідкісних слів (f < 50) оцінки частот ненадійні, цього обсягу вистачає лише для якісного опису. Це стосується насамперед гапаксів. _(Якщо у вас в методичці інша таблиця похибок, замініть цю таблицю на свою.)_

## ІІ. Основна частина: укладання ЧС

### 2.1. Використані інструменти

| Етап | Інструмент |
| --- | --- |
| Токенізація (речення, слова) | `tokenize_uk` |
| Лематизація та частиномовна розмітка | `pymorphy3` (сумісна наступниця `pymorphy2`, бо `pymorphy2` не працює на Python 3.11+); український словник `lang='uk'` |
| Зберігання та агрегація | `sqlite3` (запити `SELECT … COUNT … GROUP BY`) |
| Таблиці, експорт у Excel | `pandas`, `openpyxl` |
| Ключові слова | `scikit-learn` (`TfidfVectorizer`) |

### 2.2. Алгоритм

1. Текст читається з кодуванням `utf-8-sig` (прибирається BOM).
2. `tokenize_sents` ділить текст на речення, `tokenize_words` — на слова. Беруться лише слова, що починаються з літери, тобто розділові знаки й числа не рахуються. Перші 20 000 слововживань утворюють вибірку (клас `Sample`).
3. Кожне слововживання отримує номер підвибірки `part = індекс // 1000 + 1` (1…20).
4. Для кожного слова (клас `Word`) визначається: слово як у тексті, словоформа (нижній регістр), лема, частина мови (POS-тег). Результат аналізу кешується, щоб кожну форму аналізувати лише раз. Береться перший (найімовірніший) розбір pymorphy.
5. Усе записується в базу `freq_<назва>.db`. Усі частотні таблиці будуються **агрегуючими SQL-запитами**; `COUNT(*)` рахує кожне слововживання, тому повтори враховуються.
6. Таблиці експортуються в `tables_<назва>.xlsx`.

### 2.3. Структура бази даних

| Таблиця | Призначення | Стовпці |
| --- | --- | --- |
| `sentences` | речення вибірки | `sent_id`, `sentence` |
| `words` | усі слововживання з анотацією | `id`, `sent_id`, `part`, `word`, `clean_word`, `lemma`, `pos` |
| `dict_of_freq` | **БД_ЧС** (Варіант 2: частина мови + лема + словоформа) | `id`, `pos`, `lemma`, `wordform`, `abs_freq`, `part_1 … part_20` |
| `lemma_freq` | **БД_ЧС_лем** | `id`, `lemma`, `abs_freq`, `part_1 … part_20` |
| `pos_freq` | **БД_ЧС_ЧМ** | `id`, `pos`, `pos_ua`, `freq`, `part_1 … part_20` |
| `tfidf` | ключові слова за TF-IDF (по лемах) | `id`, `lemma`, `tfidf` |

Приклад запиту, яким будується БД_ЧС (абсолютні частоти у вибірці та в кожній підвибірці):

```sql
INSERT INTO dict_of_freq (pos, lemma, wordform, abs_freq, part_1, ..., part_20)
SELECT pos, lemma, clean_word, COUNT(*), SUM(part = 1), ..., SUM(part = 20)
FROM words
GROUP BY pos, lemma, clean_word
ORDER BY COUNT(*) DESC, clean_word;
```

БД_ЧС_лем і БД_ЧС_ЧМ формуються аналогічно, групуванням за `lemma` та `pos`.

## Висновки

1. Укладено автоматично по 3 частотні бази (словоформ, лем, частин мови) для двох художніх повістей з вибіркою 20 тис. слововживань і 20 підвибірками, плюс таблиці речень, слововживань та TF-IDF.
2. Текст Коцюбинського має вищу лексичну різноманітність (TTR 0,334 проти 0,282; більше різних лем) і значно більшу частку іменників (34 % проти 28,9 %). У Хвильового більше займенників (13,3 % проти 8,8 %) та дієприслівників, довші речення (9,3 проти 8,0 слів). Це узгоджується з розмовно-діалогічною, «інтелектуальною» манерою Хвильового та описовою, предметною манерою Коцюбинського.
3. Структура ЧС (домінування службових слів і/або іменників, гапакси ~2/3 словоформ) типова для художніх текстів.
4. TF-IDF виокремлює специфічну лексику та імена персонажів. Оскільки корпус складається лише з двох документів, IDF малоінформативний (слова, що є в обох текстах, штрафуються однаково), тому результат слід розглядати як ілюстративний.

## Обмеження (на що варто звернути увагу)

* **Автоматична лематизація не ідеальна.** Береться перший розбір pymorphy без контексту, тому трапляються помилки: напр. усічена лема «анарх» (від форм слова «анархіст»), «вон» (від «вони»), «йога» (від «його»), «мен» (від «мене»), «як» іноді позначено як іменник. Слова «вже», «ще», «теж» отримали `UNKN`, і так само вигуки (`ах`, `ой`, `ох`), діалектизми.
* Саме через це в топі TF-IDF можуть бути службові слова на кшталт «бути», «до», «як» — їхній POS-тег було визначено як повнозначний.
* Вибірка — початковий фрагмент твору, а не випадкова; для Хвильового це 2/3 повісті. Теоретично частоти можуть відрізнятися від частот у повному тексті.
* Архаїчні й діалектні форми (`єсть`, `сахарня`) можуть лематизуватися помилково.
